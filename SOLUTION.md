# Решение

## Сколько заняло

Около 45 минут от клонирования до пуша (по истории коммитов: 16:27 → 17:11), плюс время на ручную проверку в браузере. Бо́льшую часть кода писал ИИ-агент, я ставил задачи, принимал решения по процессу и проверял результат.

## Что сделано и что не успел

Сделано всё из частей 1–3:
- экран «Матчи тура»: загрузка с `MATCHES_URL`, карточки (хозяева/гости, счёт, если есть, дата в поясе устройства, статус по-русски);
- состояния: загрузка, ошибка с «Повторить», пустой экран, отдельное сообщение для пустой категории фильтра;
- фильтр «Все / Предстоящие / Завершённые»;
- кнопка «Обновить» и pull-to-refresh (на нативе), подпись «Обновлено N сек назад»; если обновление упало, список остаётся, появляется баннер, а «N сек» не сбрасывается;
- звёздочки на каждой карточке, оба бага из части 2 исправлены.

Тесты (jest-expo + Testing Library, `npm test`): разбор ответа, фильтр, сортировка, форматирование, хук загрузки (ошибки, гонка запросов, размонтирование), интеграционные тесты экрана и отдельные тесты, воспроизводящие жалобы тестировщика.

Из «если останется время» выбрал **тесты на логику фильтра**. Фильтр — главное место, где может «потеряться» матч, поэтому есть отдельный тест на инвариант «Предстоящие + Завершённые = Все». Сохранение избранного между запусками не делал.

## Решения

- **Фильтр.** «Завершённые» — только `finished`. Всё остальное — «Предстоящие»: `scheduled`, `live` (матч ещё не закончен, его результат интересен), `postponed` (матч ещё не сыгран) и любой неизвестный статус. Так каждый матч попадает ровно в одну вкладку, и «Предстоящие» + «Завершённые» = «Все».
- **`postponed` с `startsAt: null`.** Показываю «Дата уточняется» вместо «Invalid Date». В сортировке по времени начала такие матчи идут в конец.
- **`live`.** Показываются текущий счёт и минута («Идёт · 67'»), карточка выделена красной рамкой.
- **`score: null`** — вместо счёта «—». Счёт `0 : 0` — это счёт, а не отсутствие счёта (проверка `score ? …`, а не по значениям).
- **Неизвестный статус** показывается как есть, а не падает и не пропадает.
- **Битые данные.** Если ответ целиком не того формата или пришёл HTTP-ошибкой, показывается экран ошибки. Отдельный матч без `id` или команд пропускается, остальные показываются.
- **`MATCHES_URL`.** В шаблоне был плейсхолдер `OWNER/REPO` (по нему 404). Подставил адрес этой копии репозитория, как и предполагал комментарий в `config.ts`.
- **Гонки.** Каждый новый запрос отменяет предыдущий (`AbortController`), поэтому ответ старого запроса не перезапишет свежий.

## Баги из части 2

Сначала каждая жалоба была воспроизведена тестом, который ведёт себя как пользователь: нажимает звёздочки и ждёт время на поддельных часах. Эти тесты закоммичены красными (`test: воспроизведение жалоб…`), исправления — отдельными коммитами.

1. **Звёздочки.** `isFavorite` проверял `Boolean(favorites.indexOf(id))`. Для матча не в избранном `indexOf` возвращает `-1`, а `Boolean(-1)` — это `true`, поэтому при старте горели все звёзды. Для первого добавленного матча индекс `0`, то есть `false`, и он «гас вместо того, чтобы загореться». Кроме того, `toggle` менял массив на месте (`push`/`splice`) и передавал в `setFavorites` ту же ссылку. React сравнивает состояние по ссылке, решал, что ничего не изменилось, и не перерисовывал. Изменения проявлялись только при случайной перерисовке, отсюда «непредсказуемо». **Исправление:** `includes` и новый массив через функциональный `setFavorites(prev => …)`.
2. **«Обновлено N сек назад».** Эффект с пустыми зависимостями создал интервал один раз, и его колбэк навсегда «запомнил» `seconds = 0` (устаревшее замыкание). Каждую секунду выполнялось `setSeconds(0 + 1)`, поэтому число застывало на 1. Проп `since` вообще не использовался, так что после обновления сбрасывать было нечему. Интервал не очищался и продолжал работать после размонтирования. **Исправление:** секунды вычисляются от `since` (`now − since`), эффект зависит от `since`, а в cleanup есть `clearInterval`.

## Как я использовал ИИ

**Инструмент:** Claude Code (модель Opus 5.5) в режиме агента.

**Как строил работу:**
- Прежде чем клонировать, попросил агента проверить репозиторий на безопасность: нет ли install-скриптов в `package.json` и lock-файле и нет ли подозрительных инструкций в `AGENTS.md`.
- Попросил составить план по README и только после этого реализовывать: по шагам, с коммитом на каждом этапе.
- Поставил условие: баги из части 2 должны быть **сначала воспроизведены тестами**, которые ведут себя как пользователь (нажимают звёздочки, ждут время), и падать на исходном коде, а затем исправлены. Поэтому в истории отдельный красный коммит с тестами, а после него фиксы.
- Попросил в конце два независимых этапа проверки. Первый — живой прогон в браузере: Playwright, 27 сценариев, скриншоты, которые агент сам просматривал. Второй — ревью отдельным агентом, который не видел процесса разработки. Ревьюер вернул старый код коллеги и убедился, что тесты на баги на нём падают.
- Сам запускал приложение в браузере и проверял сценарии из жалоб тестировщика.

**Где ИИ ошибался и как это заметили:**
- Первый тест на «звезда гаснет» на исходном коде случайно проходил: без перерисовки звёзды и так «горели». Это вскрылось, потому что тест-воспроизведение обязан был упасть на старом коде. Добавили перерисовку экрана по постороннему поводу (как при смене фильтра), и симптом воспроизвёлся.
- Тест на утечку интервала через `jest.getTimerCount() === 0` падал даже после исправления: планировщик React держит свои таймеры. Заменили его на точную проверку пар `setInterval`/`clearInterval`.
- Агент один раз принял сокращённый вывод `tsc` за «ошибок нет», хотя TypeScript 6 перестал автоматически подключать `@types/jest`. При повторном запуске ошибки всплыли, исправили `tsconfig`.
- Живой прогон нашёл то, что юнит-тесты пропустили: react-native-web игнорирует `accessibilityState`, поэтому в вебе у выбранной вкладки не было `aria-selected`. Ещё на десктопе карточки растягивались на всю ширину.

## Что улучшил бы, будь ещё 2 часа

- Сохранение избранного между запусками (`AsyncStorage`, работает в Expo Go).
- Автообновление, пока на экране есть `live`-матчи.
- Группировка по дням с заголовками и поиск по названию клуба.
- Тёмная тема и проверка доступности со скринридером.
